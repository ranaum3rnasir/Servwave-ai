# Real-device release checklist

What a person checks on real phones and tablets before a release, because emulation cannot show it:
the on-screen keyboard, the notch and home indicator, the Home Screen app, in-app browsers, real
touch gestures and screen readers.

- **Rubric:** TEST-07 (mobile compatibility rubric). Every item below carries the rubric ID it
  confirms and the mobile slice that owns the fix.
- **Geometry is not checked here.** Overflow, target sizes, input font sizes, overlays inside the
  viewport and scroller reach are measured by the local mobile Playwright gate at device sizes.
  This list covers only what that gate cannot see.
- **The QA briefing** ([qa-briefing.md](qa-briefing.md)) points here for real-device testing.

## When to run it

- Before each promotion to production that touches the shell (top bar, drawer, page frame),
  overlays and dialogs, the scheduler, communication (texts, chat, email, calling) or the public
  estimate and invoice pages.
- Run every item whose owning slice has landed. An item whose owning slice has not landed yet is
  recorded as **pending**, never as passed.
- The first full run on hardware is mobile slice 73: the run sheet and record are [real-device-run-01.md](real-device-run-01.md).

## Setup

- Use deployed **staging** and a staging test account in the demo organisation. Never a real
  customer's organisation, and never production data.
- Calling items (RD-13) use only the staging test phone, and only with Ran's OK for that run. Do
  not text or call a customer number.
- Install the app to the Home Screen on one iPhone and one Android phone before starting; several
  items need the installed app.
- After a deploy, close and reopen the installed app (or reload twice) so the new version is
  running, not a cached one.

## Adding an item (for later slices)

A slice whose fix can only be confirmed on hardware appends a row to the Items table in the same
shape:

- the next free `RD-NN` ID (never renumber existing rows);
- the rubric ID or IDs it confirms;
- its own slice number in `Owner`;
- what to check, where (browser and device codes from the tables above) and when it passes.

The guard test `frontend/src/__tests__/real-device-checklist.test.ts` fails if a row lacks a rubric
ID or an owning slice, if a device-only rubric item loses its row, or if a browser or device the
plan requires is dropped.
